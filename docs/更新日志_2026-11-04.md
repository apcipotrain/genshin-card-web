## 账号业务接入 Java

新增 Spring Boot 4.1.2 / Java 21 账号服务。原有 Node.js + Express + Socket.IO 服务继续管理房间、实时通信和对局；Java 负责账号与持久化。前端继续发送原有 Socket.IO 事件，由 Node.js 的 HTTP 客户端转发账号请求。

```text
网页：LoginPage / SocketManager
  │ Socket.IO：login、update_profile 等事件
  ▼
Node.js：server/index.ts → AccountApiClient.ts
  │ HTTP：/api/auth/login 等接口
  ▼
Java：AccountController → AccountService → AccountRepository
  │ JDBC / SQL
  ▼
H2 文件数据库
```

Java 已接入的业务包括注册、登录、退出、个人资料、设置合并、PVE 关卡最高星级、经验及 PVP 身份胜率统计。默认 Java 端口为 `8080`、Node.js 为 `3457`、网页为 `3000`。

数据库采用 H2 文件模式，默认数据目录为 `java-backend/data/`，首次启动自动建表，不需要单独安装数据库。当前没有接入 MySQL。

## 数据迁移和登录会话

- 启动时读取旧 `server/accounts.json`。导入在事务中完成，保留源文件；重复启动跳过数据库中已存在的账号，不用旧文件覆盖新的修改。
- 新注册密码使用 BCrypt。旧 SHA-256 密码在成功登录后升级为 BCrypt；超过 BCrypt 72字节限制的旧密码采用带 `{bcrypt-sha256}` 标识的预处理格式，保持兼容。
- 登录令牌使用随机值，数据库仅保存摘要与过期时间，默认有效期7天。退出登录撤销当前令牌；数据库可保留服务重启后的有效会话。
- Java `/api/health` 在旧账号导入及应用就绪后返回成功，启动器等待就绪后再启动游戏服务。

## PVP 结算和故障处理

PVP 经验由游戏服务计算。Java 内部接口在一个事务中更新经验和身份胜率统计，用“账号 + 操作编号”记录已完成操作，避免并发请求或重试重复入账；相同编号携带不同结算参数时会拒绝。

Node.js 在提交前，将结算命令保存到 `.runtime/pvp-settlements.json`。接口失败时保留任务并重试，进程重启后也能读取待提交任务。确认成功后才移除命令；队列文件不保存玩家 Token。

内部结算接口通过 `X-Game-Service-Key` 认证。启动脚本自动生成或读取本地共享密钥，浏览器不接收该密钥。账号请求改为异步后，同一 Socket 的相关操作依次处理，并检查等待期间是否已断线，减少过期响应修改连接状态的问题。

## 启动和验证

```powershell

npm run server             # 等待账号服务后运行游戏服务
npm run dev                # 单独运行网页
npm run backend:test       # Java 测试
npm run backend:package    # Java 测试和打包
npm run typecheck          # 前端及服务端 TypeScript 类型检查
npm test                   # TypeScript 测试
npm run build              # 前端构建
npm run test:backend:smoke  # 已启动服务的跨服务验证，会创建测试账号
```
